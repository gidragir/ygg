# 🤖 AGENTS.md — Архитектурное руководство репозитория `ygg`

> **Назначение:** Независимый кроссплатформенный CLI-менеджер модулей конфигураций (`ygg` — от *Yggdrasil*).  
> **Рантайм:** Nushell (`nu >= 0.116`), `TOML`, `git`, `just` (`set shell := ["nu", "-c"]`).  
> **Целевые ОС:** Linux (CachyOS / Arch и др.), Windows 11 / Server (Non-Admin, без Developer Mode), macOS.

## 🔒 2. Жёсткие инварианты безопасности и архитектуры

1. **Абсолютная изоляция хоста при разработке и тестах (ZERO HOST MUTATION):**
   * Ни один тест и ни один отладочный запуск `ygg` в рамках разработки не имеют права читать или модифицировать реальные `~/.ygg`, `~/.config` или `$HOME` рабочей станции.
   * Все тесты обязаны выполняться строго внутри временных каталогов (`/tmp/ygg-test-*`) с явно заданными `YGG_HOME`, `YGG_SANDBOX` и `YGG_MOCK_PKG_LOG`.

2. **Чистота ядра `ygg` от личных репозиториев:**
   * Движок `ygg` не должен содержать захардкоженных имён пользовательских модулей (`omni-dotfiles`, `ai-dotfiles`, `hermes` и т.п.). Вся логика строится строго вокруг контракта `host.toml` и модульного `ygg.toml`.

3. **Безопасность удаления ссылок (`Zero-Data-Loss`):**
   * Удаление ссылок (`unlink` / `prune`) обязано проверять, что целевой путь является именно симлинком или NTFS Reparse Point (`($p | path type) == "symlink"` на Unix), и удалять **только саму ссылку**, никогда не выполняя рекурсивное удаление содержимого целевых директорий.
   * Бэкапы заменяемых обычных файлов сохраняются централизованно в `$YGG_HOME/.state/backups/<timestamp>/` — создание файлов `.bak` внутри `~/.config/` запрещено.

4. **Кроссплатформенность и Windows Non-Admin:**
   * Никаких зависимостей от `/bin/bash` в логике модулей `src/*.nu` (кроме платформенного враппера `bin/ygg` и `scripts/install.sh`).
   * На Windows запрещено требовать права администратора или Developer Mode: для каталогов используется `cmd /c mklink /J` (NTFS Junction), для одиночных файлов и `[save]` — `3-way hash sync` копирование, для скриптов в `bin/` — автогенерация парных `.cmd`-шиммов.

5. **Формат манифестов и отсутствие шаблонизаторов:**
   * Все пользовательские манифесты имеют формат `TOML` (`host.toml`, `secrets.toml`, `ygg.toml`, опциональные `packages.toml`, `links.toml`, `env.toml`, `aliases.toml`). Внутренний машинный стейт — `.state/state.json`. Внешние шаблонизаторы (`.tmpl`) не используются.

6. **Терминал и поиск (`rtk` + `fd` / `rg`):**
   * Все shell-команды запускаются строго с префиксом `rtk` (`rtk nu`, `rtk just`, `rtk git`). Использование GNU `find` и `grep` запрещено.

## 🗂 3. Глоссарий проекта

* **`Ygg Home` (`~/.ygg/` или `$env.YGG_HOME`)** — единая папка пользователя на хосте (`host.toml`, `secrets.toml`, `modules/`, `.state/`).
* **`Module` (`ygg.toml`)** — независимая папка или Git-репозиторий с пакетами, ссылками и опциональным `setup.nu`.
* **`Scope` (`[scope.<name>]`)** — фильтр железа/роли (`pc`, `asus`, `work`) или автоматически активируемый фильтр ОС (`linux`, `windows`, `unix`, `cachyos`).
* **`Host` (`host.toml`)** — список подключённых модулей компьютера, их активных `scopes`, исключений `exclude` и параметров `config`.
